## 4 CRITICAL CORE PARSING REQUIREMENTS

Your implementation must strictly solve common extraction bugs using these structural architectural patterns:

1. **Physical Layout Segmentation (`layout_segmenter.py`):**
   Do not process an invoice as a single continuous text stream. The layout engine must identify and isolate the bottom footer section (containing Subtotal, Tax, and Total) away from the central line-item tabular container. The table parser must *only* evaluate the line-item container to ensure summary elements are never appended as line items.

2. **Mathematical Validation Guard (`reconciliation_engine.py`):**
   Implement a hard data-routing filter that cross-checks structural components. If the sum of individual line item prices (`total_price`) plus `tax_amount` does not mathematically balance with the grand `total_amount`, the engine must automatically lower the confidence score, drop the synchronous ruleset, and route the raw buffer to `vision_llm_client.py` for visual conflict resolution.

3. **Strict Document Type Gating (`ml_classifier.py`):**
   If financial tokens (e.g., currency symbols, "USD", "Tax", "Invoice", "Total") are heavily present, or if any financial line items are successfully mapped, the system must prevent the `document_type` from classifying as a "resume" unless an absolute 0.99 confidence override threshold is satisfied.

4. **Floating-Point Precision Normalization (`base.py`):**
   Pydantic schema properties must enforce automated decorators to catch IEEE 754 float precision anomalies. Scores or extractions such as `0.9000000000000001` must be instantly truncated and serialized to clean, standard two-decimal floats (e.g., `0.90`).
